// 01 — THE PRODUCT

One assistant. Four zones. Zero guesswork.

The clerk scans a standard 1D barcode; Velo does the searching, sorting and remembering. The human always has final say — Velo organizes, recommends and alerts, never acts alone.

// 03 — THE TECH STACK

Four layers. All of it local.

A deliberately small, open stack. Every layer runs inside Company A's own network — no external API keys, no proprietary data on the public internet, no cloud outage that can stop a shift.

  1. L1
    DEVICE

    Clerk app

    Next.jsPWAEAN-13 / Code-128

    WHAT IT DOESA mobile web app that turns any store smartphone into a guided 1D barcode scanner — receiving, put-away and refill tasks in one place.

    WHY IT'S STRONGReplaces $1,800+ infrared scanner guns with phones clerks already carry. No app-store install, works offline for core scan flows.

  2. L2
    CORE

    Velo hub

    FastAPIWebSocketsPOS webhook

    WHAT IT DOESThe central service: one source of truth for stock, tasks and bays. A POS sale fires a webhook; the refill engine pushes a task to the right clerk instantly.

    WHY IT'S STRONGAsync Python keeps latency low under shift-peak load. Real-time push means no polling, no stale shelves, no paper checklists.

  3. L3
    DATA

    Store data

    PostgreSQLpgvectorFEFO batches

    WHAT IT DOESRelational stock, batches and expiry dates alongside vector embeddings of 30,000+ SKUs and BR18 / TEK17 / BBR building codes.

    WHY IT'S STRONGOne database for transactions and semantic search — fewer moving parts, one backup, fully auditable by IT.

  4. L4
    INTELLIGENCE

    Local AI

    Ollama / vLLMLlama 3.2 · Qwen 2.5BGE-M3

    WHAT IT DOESQuantized open-weight models answer clerk questions with RAG over the store catalog — in under two seconds, on a local GPU.

    WHY IT'S STRONGZero external calls. Open weights mean no vendor lock-in, no per-token bill, and nothing leaves the building.

// 06 — QUESTIONS

Fair questions, straight answers

Why start with the store clerk, not the delivery fleet?

Every downstream system — transfers, fulfilment, delivery — consumes inventory truth created at the shelf and the bay. Fix the source first and the network scales itself; automate later and you automate chaos.

Is local AI actually fast enough?

Quantized 3B–7B models on a single on-premise GPU answer grounded questions in under two seconds via RAG. The workflow loop — scans, thresholds, tasks — is deterministic logic that doesn't touch the LLM, so the store keeps running even if the GPU naps.

What happens to the legacy infrared scanners?

Retired. A ruggedized smartphone with camera scanning (EAN-13 / Code-128 at under 150ms) replaces $1,500–$2,200 terminals plus 20% annual maintenance contracts — a cut of more than 75% in hardware spend.

How do three markets stay different?

One core, local configuration. Denmark starts with paperless receiving, Norway with standardized zone workflows, Sweden connects fulfilment last. Same platform, three rollout clocks.
